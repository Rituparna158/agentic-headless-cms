**API Tokens** allow external applications—such as public frontends, mobile apps, scheduled sync jobs, or autonomous AI agents—to authenticate with the CMS API securely without using personal user credentials.

Located under **Roles & Access** &rarr; **API Tokens** (`/roles-access?tab=tokens`), tokens can be restricted to specific roles to enforce least-privilege access.

---

## Creating an API Token

To generate a new token:

1. Navigate to **Roles & Access** &rarr; **API Tokens**.
2. Click **Create API Token**.
3. Fill in the token details:
   - **Name**: A descriptive name identifying the consuming application (e.g., `Production Next.js Website` or `Mobile App Read-Only`).
   - **Role**: Select the role determining what resources this token can access. For example, assign a `Viewer` role for public websites, or an `Editor` role for automated content ingestion pipelines.
4. If Multi-Factor Authentication (MFA) is enabled on your administrator account, confirm the action with your 6-digit authenticator code.
5. Click **Create**. Copy the generated token immediately—for security reasons, the full key is displayed only once.

---

## Revoking a Token

If a token is compromised, rotated, or no longer needed:

1. Navigate to **Roles & Access** &rarr; **API Tokens**.
2. Locate the token and click **Revoke**.
3. The token is immediately deleted and invalidated. Any subsequent requests using that token will be rejected with a `401 Unauthorized` status.
